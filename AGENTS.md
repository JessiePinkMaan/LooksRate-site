# AGENTS.md — постоянные правила для агента (LoxRate)

Этот файл читается всегда. Он короткий намеренно. Детали — в `TZ_LOXRATE_SITE.md` (читать по разделам) и `docs/PHASE_PROMPTS.md`.

## Что строим
Сайт-визитка и закрытый клуб для Telegram-проекта LoxRate (канал `t.me/loxrating`, бот `@loxrate_bot`). Вайб: тёмный подвал, «Бойцовский клуб», стоицизм, золотое яблоко раздора, дарк-люкс (кожа/сталь/заклёпки — только как фактура). Флагман — вкладка «Основатели»: две таинственные фигуры, камера сверху вниз, динамический свет. Функции: видео-хранилище с уровнями доступа, админка, платные тарифы, ранги и XP, идеи, комментарии.

## Источник истины и порядок приоритета
1. `TZ_LOXRATE_SITE.md` → 2. `docs/PHASE_PROMPTS.md` → 3. `docs/SNIPPETS.md` (только отправная точка) → 4. твоё суждение (с записью в `DECISIONS.md`).
Работай **по фазам**. После фазы — отчёт (формат: ТЗ §26.3) и **остановка до слова «дальше»**.

## Язык
UI, тексты, документация — русский. Идентификаторы, имена файлов, сообщения коммитов — английский. Комментарии в коде — только там, где объясняют «почему».

## Команды (должны работать с фазы 0)
`pnpm dev` · `pnpm build` · `pnpm lint` · `pnpm typecheck` · `pnpm test` · `pnpm e2e` · `pnpm qa:shots` · `pnpm qa:a11y` · `pnpm qa:perf` · `pnpm db:migrate|seed|reset` · `pnpm docker:up|down` · `pnpm assets:generate`

## Жёсткие правила
1. **Не хардкодить** цены, пороги XP, тексты тарифов, тексты страниц. Тексты — `content/ru/*.json`, остальное — БД/конфиг.
2. **У каждого эффекта есть fallback** (CSS-версия) и поведение для `prefers-reduced-motion`. Есть глобальная кнопка «Отключить эффекты».
3. **Без внешней сети в рантайме dev:** шрифты через `@fontsource`, ассеты процедурные, у каждого внешнего сервиса есть локальная заглушка (ТЗ §25). Не вставляй CDN-ссылки.
4. **Секреты** — только в env. Никогда в коде, логах, коммитах, отчётах. Окружение валидируется zod-схемой при старте.
5. **Все права проверяются на сервере.** Клиентская проверка — только UX. Доступ к видео решает единственная функция `decide()` (SNIPPETS S7).
6. **Все изменения XP — через сервис `awardXp()`** (журнал `xp_events`, идемпотентность, дневные капы). Прямых `UPDATE users SET xp` нет.
7. **Аудит:** любое действие роли `editor` и выше пишется в `audit_log`.
8. **Фотосенситивность:** не более 3 вспышек в секунду, никаких стробоскопов; лампа дышит мягко (амплитуда ≤ ±10%).
9. **Гардрейлы контента (ТЗ §17.3) — обязательны:** без эротики; без инструкций по опасным практикам; без дегуманизирующих слов в интерфейсе; ранги — про дисциплину, не про внешность; фото лиц от пользователей не принимать; реальные лица основателей — только с согласия.
10. **Реальные люди и чужие фото:** не скачивать и не вставлять фотографии людей из интернета.
11. **`DEV_LOGIN`, `fake`-провайдеры и тестовые персонажи** не должны работать при `NODE_ENV=production`.

## Стиль кода
TypeScript `strict`, без `any` (исключения — с комментарием). Серверный код помечай `import 'server-only'`. Валидация входа — zod на каждой границе. Ошибки — типизированные, без проглатывания. Компоненты маленькие; бизнес-логика — в `packages/` или `lib/`, не в JSX. Тесты — рядом с кодом (`*.test.ts`). Названия — по смыслу, без сокращений-загадок.

## Рабочий цикл (на каждую задачу)
план (3–7 строк) → минимальный рабочий срез → `typecheck + lint + test` → **скриншоты** (`pnpm qa:shots`) и оценка по рубрике «вайба» (`docs/QA_AND_RISKS.md`) → до 3 итераций на компонент → небольшой коммит.
Для детерминированных скриншотов в dev/test доступен `window.__qa` (ТЗ §6.7).

## Git
Ветка на фазу: `phase/NN-name`. Небольшие коммиты, осмысленные сообщения (`feat:`, `fix:`, `chore:`, `docs:`). Без force-push. Большие бинарники (>1 МБ) не коммитить без записи в `DECISIONS.md`.

## Когда спрашивать владельца
Только если действие: тратит деньги · требует учётных данных · затрагивает юридические формулировки/возраст/возвраты · необратимо · меняет вайб, структуру страниц или состав тарифов. Остальное решай сам и записывай в `DECISIONS.md`.

## Файлы, которые ведёшь
`DECISIONS.md` (решения и отступления) · `ASSETS_TODO.md` (что нужно от владельца: фото, логотип, звуки, ключи) · `CHANGELOG.md`.

## Определение «готово» для любой задачи
Работает на desktop и mobile · `build` зелёный · есть тест на логику (не на пиксели) · UI проверен скриншотами · есть fallback и reduced-motion · нет `TODO` без записи в `DECISIONS.md` · нет `console.error` в консоли страницы.
