# DECISIONS — принятые решения и отступления

Журнал решений, которые не описаны в ТЗ однозначно, и мелких отступлений ради
производительности/доступности. Формат: `## D-N · дата · тема`, затем «Решение»,
«Почему», при необходимости — «Влияние».

## D-1 · 2026-11-05 · Пакет `docs/` не предоставлен

**Решение.** Работаю только по `AGENTS.md` + `TZ_LOXRATE_SITE.md`. Файлы
`docs/PHASE_PROMPTS.md`, `docs/SNIPPETS.md`, `docs/QA_AND_RISKS.md`,
`docs/SCHEMA.prisma`, `docs/tokens.css` создаю по мере необходимости, выводя их из ТЗ.
Приоритет источников: ТЗ → (созданные) docs → моё суждение.
**Почему.** Владелец явно выбрал вариант «работай без docs/, только по ТЗ».

## D-2 · 2026-11-05 · Точные версии стека

**Решение.** Node `24.x` (ТЗ: ≥22), pnpm `12.16`, Turborepo `2.11`,
Next.js `16.4`, React `19.3`, **TypeScript `5.9.3`**, **Prisma `7.10.1`**.
**Почему.**
- `typescript@latest` = `7.0.2` — это нативный (Go) порт, экосистема ещё
  догоняет; беру стабильную ветку `5.9.3` ради совместимости с Next 16 и
  typescript-eslint.
- `prisma@latest` указывает на `8.0.0-rc.30` (RC), а стабильный `prev` = `7.10.1`;
  `@prisma/client@latest` = `7.10.1`. Фиксирую обе части на `7.10.1`, чтобы CLI и
  клиент совпадали.
**Влияние.** Версии продублированы в `package.json` пакетов; менять только с записью здесь.

## D-3 · 2026-11-05 · Куда генерируются процедурные ассеты

**Решение.** Скрипт `pnpm assets:generate` кладёт результат в
`apps/web/public/assets/`, а не в корневой `/public/assets` из §20.
**Почему.** В монорепе Next.js раздаёт статику только из своего `public/`
(`apps/web/public`). Корневой `/public` не обслуживается без доп. настройки.
**Влияние.** В §20 путь трактуется «логически»; фактические файлы — в `apps/web/public/assets`.

## D-4 · 2026-11-05 · Дополнительный пакет `@loxrate/assets`

**Решение.** Добавляю `packages/assets` (сверх `config/db/ui` из §20) для
генератора процедурных ассетов.
**Почему.** Генератор — отдельная ответственность с собственным скриптом и
зависимостями (sharp/svg). Держать его в `ui` или `db` нелогично.

## D-8 · 2026-11-05 · Docker и локальная БД

**Решение.** `docker-compose.yml` написан (postgres/redis/minio). Локально
проверяется после установки Docker (установлен владельцем 2026-11-05).
`typecheck/lint/test/build` обязаны быть зелёными без живой БД (юнит-тесты
не ходят в БД).
**Почему.** Агент должен собирать проект даже без инфраструктуры; интеграционные
проверки БД — отдельным шагом.

## D-9 · 2026-11-05 · Prisma 7: драйвер-адаптер и `prisma.config.ts`

**Решение.** Prisma 7.10.1. `url` убран из `datasource` (в Prisma 7 не
поддерживается), строка подключения для миграций — в `packages/db/prisma.config.ts`;
клиент создаётся через `PrismaPg` (`@prisma/adapter-pg` + `pg`).
**Почему.** Так требует Prisma 7. `prisma generate` не требует живой БД, поэтому
сборка/typecheck зелёные без инфраструктуры.

## D-10 · 2026-11-05 · MinIO недоступен в текущем окружении

**Решение.** `docker-compose.yml` оставлен по ТЗ (MinIO + auto-bucket init).
Локальная проверка Фазы 0 выполнена на `postgres` + `redis`; S3 понадобится
только в Фазе 8, тогда и проверим хранилище (MinIO или внешний R2).
**Почему.** Registry-прокси окружения блокирует образы `minio/*` и `quay.io`
(401/denied); `postgres`, `redis` и `adobe/s3mock` доступны. На машинах без
этого ограничения `pnpm docker:up` поднимет все сервисы по ТЗ.

## D-13 · 2026-11-05 · Силуэты основателей из CC0-источников

**Решение.** Силуэты основателей взяты из двух **CC0**-файлов Wikimedia Commons
(`Man standing silhouette.svg` — pitr; `Silhouette of man standing and facing
forward.svg` — Madeleine Price Ball). Оригиналы лежат в
`packages/assets/vendor/` с провенансом и лицензией; `pnpm assets:generate`
извлекает path и перекрашивает в тёмный брендовый градиент.
**Почему.** Владелец явно разрешил и уточнил: запрет §7.5/§17.3 и AGENTS.md п.10
касается **узнаваемых реальных людей**, а не анонимных силуэтов. CC0 не требует
атрибуции и не создаёт лицензионных рисков. Динамический rim-свет не запекаем
в ассет — это задача сцены Фазы 4.

## D-15 · 2026-11-05 · Стенд `/_design` через rewrite

**Решение.** Файлы стенда — `apps/web/app/design/`, а путь `/_design` работает
через `rewrites` в `next.config.ts` (`/_design` → `/design`).
**Почему.** Next.js не роутит папки, начинающиеся с `_` (private folders). ТЗ
требует путь `/_design`; rewrite сохраняет его без отказа от конвенций Next.

## D-16 · 2026-11-05 · QA-скриншоты: Playwright + `next dev`

**Решение.** `pnpm qa:shots` — самодостаточный скрипт на Playwright (`@playwright/test`,
chromium): 4 ширины, отдельный кадр с курсором на интерактиве и reduced-motion,
сохранение в `qa/shots/<phase>/`. QA-сервер поднимается как `next dev`.
**Почему.** `next start` работает в production-режиме, и env-гард корректно
блокирует `DEV_LOGIN=true`/`fake`-провайдеры. Для локальных скриншотов нужен
dev-режим; production-гард не ослабляем. В продакшене скриншоты снимутся против
реального окружения (Фаза 5).
