# DECISIONS — принятые решения и отступления

Журнал решений, которые не описаны в ТЗ однозначно, и мелких отступлений ради
производительности/доступности. Формат: `## D-N · дата · тема`, затем «Решение»,
«Почему», при необходимости — «Влияние».

## D-1 · 2026-11-05 · Пакет `docs/` не предоставлен

**Решение.** Работаю только по `AGENTS.md` + `TZ_LOXRATE_SITE.md`. Файлы
`docs/PHASE_PROMPTS.md`, `docs/SNIPPETS.md`, `docs/QA_AND_RISKS.md`,
`docs/SCHEMA.prisma`, `docs/tokens.css` создаю по мере необходимости, выводя их из ТЗ.
Приоритет источников: ТЗ → (созданные) docs → моё суждение.
**Почему.** Владелец явно выбрал вариант «работай без docs/, только по ТЗ».

## D-2 · 2026-11-05 · Точные версии стека

**Решение.** Node `24.x` (ТЗ: ≥22), pnpm `12.16`, Turborepo `2.11`,
Next.js `16.4`, React `19.3`, **TypeScript `5.9.3`**, **Prisma `7.10.1`**.
**Почему.**
- `typescript@latest` = `7.0.2` — это нативный (Go) порт, экосистема ещё
  догоняет; беру стабильную ветку `5.9.3` ради совместимости с Next 16 и
  typescript-eslint.
- `prisma@latest` указывает на `8.0.0-rc.30` (RC), а стабильный `prev` = `7.10.1`;
  `@prisma/client@latest` = `7.10.1`. Фиксирую обе части на `7.10.1`, чтобы CLI и
  клиент совпадали.
**Влияние.** Версии продублированы в `package.json` пакетов; менять только с записью здесь.

## D-3 · 2026-11-05 · Куда генерируются процедурные ассеты

**Решение.** Скрипт `pnpm assets:generate` кладёт результат в
`apps/web/public/assets/`, а не в корневой `/public/assets` из §20.
**Почему.** В монорепе Next.js раздаёт статику только из своего `public/`
(`apps/web/public`). Корневой `/public` не обслуживается без доп. настройки.
**Влияние.** В §20 путь трактуется «логически»; фактические файлы — в `apps/web/public/assets`.

## D-4 · 2026-11-05 · Дополнительный пакет `@loxrate/assets`

**Решение.** Добавляю `packages/assets` (сверх `config/db/ui` из §20) для
генератора процедурных ассетов.
**Почему.** Генератор — отдельная ответственность с собственным скриптом и
зависимостями (sharp/svg). Держать его в `ui` или `db` нелогично.

## D-10 · 2026-11-05 · MinIO недоступен в текущем окружении

## D-16 · 2026-11-05 · QA-скриншоты: Playwright + `next dev`

**Решение.** `pnpm qa:shots` — самодостаточный скрипт на Playwright (`@playwright/test`,

## D-19 · 2026-11-05 · Движок движения (Фаза 2)

**Решение.** Lenis + GSAP ScrollTrigger грузятся лениво. Занавес роут-переходов —
OGL-канвас в корневом layout, отдельный чанк, 5 шейдеров T1/T2/T3/T6/T9;

выключенных эффектах. DPR ≤ 1.5.
**Почему.** ТЗ §6.5–§6.7.
**Ограничение.** Полная трёхуровневая авто-деградация по FPS (high/mid/low) пока
частичная: есть WebGL-чек, reduced-motion, effects-off и DPR-кап; FPS-монитор и
понижение качества — Фаза 5 (перф-полировка).

## D-25 · 2026-11-05 · Занавес не висит в покое (фикс красного пятна)

**Решение.** Canvas занавеса скрыт (`display:none`), пока нет перехода
(`isTransitioning`), плюс в шейдере альфа гасится при `uProgress=0`
(`a *= smoothstep(0.0, 0.04, p)`).
**Почему.** Нашёл баг: шумовой фронт T1 при `uProgress=0` оставлял красное
пятно поверх всех страниц. Диагностика Playwright подтвердила источник — canvas.

## D-26 · 2026-11-05 · Сцена «Основатели»: CSS-слои вместо R3F (пока)

**Решение.** Флагманская сцена реализована слоистой CSS/DOM-композицией (пол,
базовая лампа, фонарь за курсором, силуэты, пыль, луч) + rAF-драйвер
скролла/курсора, а не R3F.
**Почему.** Надёжность, 60 fps, работает без WebGL, деградирует в reduced-motion/
«Эффекты: выкл», меньше JS. ТЗ §7 называет R3F; R3F-версия с depth-displacement —
опциональная полировка Фазы 12. Отступление осознанное и зафиксировано.

## D-32 · 2026-11-05 · Перф-гейт

**Почему.** Lighthouse CI тяжёл; кастомный гейт достаточен для R1.

## D-51 · 2026-11-06 · Вход по логину и паролю + врата с яблоком

**Решение.**
- Регистрация и вход — обычные логин/пароль на сайте, без Telegram-бота.
  Пароль хранится как `scrypt$<salt>$<hash>` (`lib/password.ts`), проверка —
  `timingSafeEqual`. Логин приводится к нижнему регистру, 3–24 символа,
  латиница/цифры/подчёркивание.
- Первый вход на главную — врата `ThresholdGate`: только большое яблоко,
  темнота и цитаты Сенеки, Марка Аврелия и Эпиктета. Ниже — ненавязчивая
  подсказка «Нажми на яблоко».
- Клик по яблоку открывает «Регистрация» и «Войти». Формы появляются там же,
  без отдельной страницы; после успеха — прокрутка яблока, золотая вспышка
  ауры и плавное появление сайта. При `prefers-reduced-motion` — короткий
  фейд без вращения. Есть тихий путь «Осмотреться без аккаунта», иначе
  публичные страницы стали бы недоступны.
- Повторный вход в рамках вкладки пропускается по
  `sessionStorage["loxrate:entered"]="1"` (им же пользуются QA-скрипты).
  Для уже авторизованного пользователя врата не показываются.
- Профиль `/me` — сцена с одним силуэтом в свете лампы. Силуэт пользователя
  подсвечен золотом; друзья встают рядом со своими аурами и вещами.
  «Показать/скрыть друзей» — локальное состояние, по умолчанию сцена пустая.
- Косметика (`aura`, `item`, `backdrop`) хранится в `users.profile_theme`
  (JSONB), парсится через `parseProfileTheme()` с fallback на дефолт.
  Вещи — CSS-слои поверх силуэта: шляпа, шарф, плащ, цепь.
- Дружба — таблица `friendships` со статусами `PENDING/ACCEPTED/DECLINED`.
  Встречная заявка автоматически превращается в дружбу. Заявки и удаление
  проверяются на сервере; клиент только показывает.
**Почему.** Владелец просил обычную регистрацию без бота и «не шовный» вход,
а профиль — как сцену основателей, но с одним человеком и социальным слоем.

- Косметика: `ProfileStudio` держит тему в состоянии и передаёт её сцене;
  серверный action сохраняет JSON. Это исправляет «ничего не меняется».
**Почему.** Прямой список правок владельца: качество яблока, драматургия
входа, звук, манифест на главной, живой профиль и цитаты.
